# 演示脚本（面试展示用）

1. 首页选择 演示品牌甲 Alpha 与 演示品牌乙 Beta，预算 6000，首要“轻便手感”、其次“续航”（或直接打开示例）。先说明：这是演示数据，真实机型尚未核验，所以显示“待核验”。
2. 结果页：状态是“各有取舍”，倾向 A。点开第一句的“查看依据”，展示两条重量参数记录（来源、记录日期、注意事项）。
3. 点“修改偏好”，去掉“轻便手感”，只留“续航”：状态变为“更值得考虑 B”。说明这是基于已收录样本的正面/负面计数，并展示分母与“不代表购买者遇到问题的概率”。
4. 口碑维度切到“发热”，点“查看这 X 条评论”，按“负面/褒贬混合”筛选，说明两者分开统计；指出“拍照很好，但玩游戏容易热”只算影像正面与发热负面，不推出流畅度差。
5. 样本说明：展示被排除的重复、广告、机型混入、仅物流评论及原因；待复核与待分析不进入分母。
6. 打开 Alpha vs Gamma（仅参数）、Beta vs Epsilon（容量与价格口径不同、价差大）、Alpha vs 小米 17（无数据 → 证据不足）。
7. 讲 AI 层：模型只写解释，不能翻转方向；引用编号与“数字＋单位”都要通过校验，否则删除或回退基础模式；没有共享配额时默认关闭付费调用。
8. 讲缺口：真实数据、评论来源授权、评估与试用都还没做，列出下一步。
